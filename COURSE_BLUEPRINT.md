# Micro-Certification Design Studio

## Course blueprint

**Dr. Vicki Bealman's Micro-Certification Fieldbook** presents the **Micro-Certification Design Studio**, a self-paced, intermediate professional-learning course for instructional designers, faculty partners, and co-curricular program leads. Dr. Vicki Bealman is credited throughout the experience as the course author and instructor. The studio guides participants from an initial idea to a **submission-ready proposal dossier** for DeVry University curriculum or co-curricular consideration. The experience does not represent an official DeVry course, approval process, policy, academic-credit decision, or authorization to issue a credential.

The course is organized into **four module studios** rather than weekly units. A suggested completion window is four weeks, but learners may move faster or slower. The expected active workload is six to eight hours.

## Course promise and outcome

By the end of the course, a participant will be able to **design, prototype, evaluate, and document a short micro-certification whose credential claim is bounded, whose learning activities and assessment evidence are aligned, whose experience is accessible and mobile-aware, and whose risks and open institutional decisions are visible to reviewers**.

The course uses a consistent learning cycle: **learn → build → test → record evidence → request the next decision**. Each lesson includes a concise reading, three memorable design moves, one applied activity, a field-notebook entry, a reflection, and a three-part readiness check. There are no recall quizzes. Progress is sequential, and later lessons remain locked until the current lesson’s applied work is complete.

## Lesson architecture

| Lesson | Observable objective | Primary activity | Notebook artifact |
| --- | --- | --- | --- |
| **01. Frame the credential opportunity** | Draft a problem statement naming the learner, observable gap, context, and value. | Consult a stakeholder and one nonconfidential need signal. | Opportunity statement, evidence status, open questions, and placement hypothesis |
| **02. Map the learner journey and friction** | Create an end-to-end journey with accessibility considerations and prioritized friction. | Map discover through receive/share and rank three consequential barriers. | Journey summary, friction register, and inclusive design responses |
| **03. Set the competency boundary** | Write a competency with conditions, quality criteria, prerequisites, and exclusions. | Run a title-honesty and scope test. | Credential claim card and validation owner |
| **04. Align outcome, practice, and evidence** | Connect each criterion to evidence, practice, feedback, and essential content. | Build a backward-design traceability table. | Alignment map and intentionally excluded content |
| **05. Shape the 3–5 module path** | Produce a coherent short sequence with realistic active-time estimates. | Storyboard the learner’s module path and gates. | Sequence map, timing, repeated lesson anatomy, and capstone contributions |
| **06. Design assessment and credential evidence** | Draft an authentic assessment and a provisional credential record. | Define conditions, rubric, feedback, retry, reviewer role, and evidence metadata. | Assessment blueprint and credential metadata |
| **07. Choose an interaction pattern** | Select an accordion, guided wizard, mobile guide, or hybrid using explicit criteria. | Score alternative patterns against learner risk and implementation cost. | Pattern decision matrix and state definitions |
| **08. Build one representative module** | Produce a complete learning loop with feedback and evidence capture. | Prototype the hardest representative learning moment. | Prototype description or link, accessibility notes, and unresolved decisions |
| **09. Plan a small, ethical pilot** | Write a protocol with participants, tasks, measures, thresholds, privacy, and decisions. | Define what the pilot must change and the evidence that will trigger revision. | Pilot protocol and facilitator-script outline |
| **10. Run the inclusive design pass** | Document accessibility and mobile findings, owners, fixes, and retests. | Test a representative task with keyboard, zoom, responsive layout, and media checks. | Accessibility and mobile audit |
| **11. Define credential governance** | Assign accountable roles and lifecycle triggers. | Draft ownership, versioning, review, evidence stewardship, correction, and retirement rules. | Governance and lifecycle card |
| **12. Assemble the review dossier** | Produce a concise evidence-led recommendation and bounded decision request. | Reconcile the prior artifacts and write the executive recommendation. | Complete capstone dossier |

## Field notebook and submissions

The field notebook stores four independent entries per lesson: working notes, the design artifact, completion evidence, and the learner’s reflection. Entries persist in the current browser using versioned local storage. Learners should not enter identifiable student information, protected education records, proprietary employer or client materials, credentials, financial information, or other sensitive data.

Each lesson can generate a UTF-8 text file containing the learner identity, lesson objective, completion status, notes, artifact, evidence, reflection, readiness checks, deliverable, source notes, and privacy reminder. At 100 percent completion, the learner can generate a combined Markdown proposal dossier and a personalized HTML certificate of course completion. These files are **ready for manual upload or adaptation**; the website does not claim a direct LMS, Canvas, badge-platform, or institutional-system integration.

## Capstone dossier structure

| Section | Reviewer question |
| --- | --- |
| Executive recommendation and requested decision | What bounded next decision is being requested? |
| Opportunity brief and learner evidence | What verified need makes this proposal worth considering? |
| Competency claim, boundaries, and prerequisites | What exactly will the credential represent—and not represent? |
| Alignment and module sequence | How does every activity contribute to the demonstrated capability? |
| Assessment blueprint and credential metadata | What evidence supports the claim, and how will it be judged? |
| Interaction-pattern rationale and prototype evidence | Why is this delivery pattern appropriate, and what has been tested? |
| Pilot protocol, measures, and decision thresholds | What will the pilot determine, and what results trigger revision or scale? |
| Accessibility and mobile readiness audit | Which learner tasks were tested, what barriers remain, and who owns remediation? |
| Governance, lifecycle, risks, and authority questions | Who maintains the claim and what institutional decisions remain open? |

## Proposed review rubric

| Dimension | Ready for limited pilot | Revise before pilot |
| --- | --- | --- |
| **Need and institutional fit** | The learner, performance gap, context, and proposed pathway are evidence-supported; assumptions are labeled. | The proposal begins with a topic, generic audience, or unverified institutional claim. |
| **Credential claim** | The title, competency, conditions, success criteria, prerequisites, and non-claims agree. | The title is broader than the evidence or the performance cannot be observed. |
| **Alignment** | Every criterion maps to final evidence, rehearsal, feedback, and essential instruction. | Activities or content cannot be traced to the credential claim. |
| **Assessment integrity** | Conditions, rubric, feedback, retry, accommodations, reviewer role, and evidence handling are explicit. | The award is based on attendance or completion while being described as competency. |
| **Experience design** | The selected pattern addresses documented friction and includes visible states, resume behavior, and feedback. | Navigation, gates, errors, or completion requirements are ambiguous. |
| **Accessibility and mobile readiness** | Complete learner tasks were tested with keyboard, zoom/reflow, responsive layouts, media alternatives, and remediation ownership. | The proposal relies on an unsupported compliance statement or automated scan alone. |
| **Pilot and evaluation** | Measures have predeclared thresholds and decision rules; privacy and de-identification are addressed. | The pilot gathers opinions without linking results to design decisions. |
| **Governance** | Academic, operational, assessment, technology, and issuance responsibilities are proposed and marked for confirmation. | The proposal assumes an owner, platform, approval body, or policy that has not been authorized. |

## Evidence base and boundaries

The course uses DeVry’s public institutional and academic-quality materials as context for career-centered learning, measurable outcomes, applied learning, and continuous improvement.[1][2] It uses the Quality Matters Higher Education Course Design Rubric, Seventh Edition, as an external design reference for alignment, assessment, learner support, usability, and accessibility; using the framework does not constitute an official QM review or certification.[3] WCAG 2.2 provides the technical accessibility baseline for the web learning experience, while final conformance requires evaluation of the implemented content and platform.[4] The 1EdTech Open Badges materials inform achievement, criteria, issuer, recipient, evidence, verification, privacy, and lifecycle planning; technical conformance alone does not establish academic validity or DeVry approval.[5]

Public sources do not establish DeVry’s internal micro-certification definition, credit treatment, approval committee, timeline, staffing model, badge platform, evidence-retention policy, or issuance authority. The dossier therefore treats those items as **questions for authorized stakeholders**, not as facts.

## Delivery notes

The implemented website uses a **Curriculum Fieldbook** visual system with deep navy, warm paper, restrained gold, and cobalt process cues. The instructor profile uses the portrait and scanned signature supplied by the user; no biography, institutional title, or additional credential has been invented. The scanned signature is also embedded in the downloadable completion certificate so it remains available when the HTML file is opened offline. Dr. Bealman's authorship appears in lesson exports, the combined proposal dossier, the completion certificate, course header, instructor section, and footer.

The live application's **Register** controls open the user-supplied Microsoft Forms registration page in a new tab. Fieldbook workspaces remain directly accessible in the application, so returning participants do not depend on an internal registration flag. Learner identity used in proposal exports is entered separately in the browser-saved Notebook. Dr. Bealman’s instructor section includes a short first-person welcome beside the supplied headshot and scanned signature.

The authenticated internal registration dashboard remains available for any records collected before the Microsoft Forms transition. It no longer receives submissions from the live application. Authorization is enforced by the server rather than by navigation visibility, and the dashboard retains its reminder that exported personally identifiable information belongs only in approved systems.

Completed participants can download a styled, personalized **Proposal Dossier PDF** in addition to the editable Markdown dossier and completion certificate. The PDF uses a 15-page minimum structure with a custom cover that prominently displays the participant’s name, role or affiliation, proposed pathway, and completion date derived from the latest completed lesson. It also includes Dr. Bealman’s embedded signature, an executive map, all twelve lesson artifacts, evidence, reflections, checks, external references, privacy guidance, and page numbers. The generator runs in the browser, so proposal content is not uploaded to the registration database.

The site includes accessible light and dark themes, responsive layouts, visible focus treatment, reduced-motion support, four generated editorial module plates, and four standalone process visualizations for manual LMS integration. Fieldbook notes and proposal content remain local by default; direct Canvas integration, institutional approval routing, and server-backed credential verification remain out of scope until authorized requirements are available. The retired GitHub Pages static companion and its `/docs` source package have been removed.
